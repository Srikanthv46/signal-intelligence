# Porting a verified Python capability to the C++ library

The Python package (`python/spectrum_intel`) is the reference; the C++ library (`c++/`) is
the production build for edge devices. Only work that is verified in Python (on the bench and
on `testdata/`) is ported, and a port is done when the parity check passes. This file is the
recipe.

## Layout

```
c++/
  include/spectrum_intel/   public API: spectrum_intel.hpp (Engine, IQBlock, StreamAnalyzer), c_api.h
  src/core/                 numpy/scipy equivalents + shared records (python core/ + model.py)
    types.hpp               cf, cd, fvec, dvec, cfvec, Mat<T>, Json (ordered_json), py_round
    fft.hpp                 numpy/scipy FFT conventions on pocketfft
    npcompat.hpp            si::np::   numpy functions (percentile, median, interp, polyfit, convolve, ...)
    ndimage.hpp             si::ndi::  scipy.ndimage (uniform/median/grey filters, label, find_objects, ...)
    signal.hpp              si::sig::  scipy.signal (find_peaks, firwin, butter/sos, resample_poly, welch, stft)
    dsp.hpp                 Channelizer (python core/dsp.py), burst_mask
    spectral.hpp            python core/spectral.py (SpectralChannelizer, find_spurs, cp_metric, ...)
    seq3gpp.hpp, ofdm15k.hpp, bands_india.hpp   the python core modules of the same names
    model.hpp               Box, Signal, Emission, Decoded, Image
    spectrogram.hpp         Spectrogram, DetectResult (records receivers may read)
    parallel.hpp            threads(), parallel_for, pmap (ordered)
    pyfmt.hpp               py_repr, py_float_repr, fmt(): report strings exactly as Python prints them
    timeutil.hpp            UTC times as Python's isoformat()
  src/io/sigmf.hpp          Capture, load_sigmf, convert_iq
  src/decode/               plugin interface (plugin.hpp), EmissionReceiver adapter, registry
  src/detect, features, classify, report, analyze.cpp   the pipeline (python detect/, features/, ...)
  src/api/                  Engine, response builder, contract (schema/ compiled in), C API
  src/receivers/<name>/     one folder per receiver, mirroring python/spectrum_intel/receivers/<name>/
  apps/si_analyze.cpp       CLI (also drives the parity check)
  tests/unit/               doctest unit tests (test_<area>_*.cpp)
  tests/vectors/            reference vectors made by the real numpy/scipy/Python receivers
  tools/parity.py           C++ vs Python on testdata
  tools/check_modularity.py
```

## Rules (same as the Python package)

- A receiver's DSP files include only `core/`, `io/` and its own folder (`receivers/<name>/...`).
  `plugin.cpp` is its only adapter to the pipeline and may include `decode/`. Nothing outside
  `src/receivers` includes a receiver; the registry is generated by CMake from the folders.
  `tools/check_modularity.py` enforces this.
- A receiver folder holds `*.hpp/*.cpp`, `plugin.cpp` and a `README.md` (what it does, how, its
  parity status). In `plugin.cpp`:
  ```cpp
  namespace si::rx::<name> {
  void register_plugins(si::PluginList& out) { out.push_back(std::make_unique<MyDecoder>()); }
  }
  ```
  with `name()` = the Python plugin's `name`, `package()` = the folder name, and `after()` = the
  Python plugin's `after`.
- Never guess silently: labels below 0.5 confidence are `unknown`; inferred labels say "-like";
  every signal keeps its `detection` and `decoded.steps` provenance — exactly as Python.
- Licences: the library must stay free of GPL/AGPL code. pyModeS (GPL-3) and py3gpp (AGPL-3)
  may be used only as black-box test oracles; implement from the public standards
  (DO-260B / ICAO Doc 9871, 3GPP TS 36.211/38.211/38.212). The DroneID decoder
  (`../droneid-decoder-reference`, armoryshield) is in-house and may be ported.

## Style

C++17, `.clang-format` (Google style, 120 columns), `snake_case` functions and variables, `CamelCase` types,
`kConstant` constants, one namespace per receiver (`si::rx::<name>`). A comment per function says which Python
function it reproduces and anything that differs. No raw `new`/`delete`, no global mutable state (caches go in
`ctx.cache`), no exceptions across the public API (the Engine turns them into `errors[]`).

## Translating Python

| Python | C++ |
|---|---|
| `np.float32` / `complex64` arrays | `fvec` / `cfvec` (keep the same dtype: decisions sit on thresholds) |
| `float64` / `complex128` | `dvec` / `cdvec` |
| 2-D arrays | `Mat<T>` (row-major, `m(r, c)`) |
| dicts that reach the report (features, detection, decoded fields) | `Json` (ordered; insert keys in Python's order) |
| `round(x, n)`, `round(x)` | `py_round(x, n)`, `py_round_int(x)` |
| f-strings in evidence/steps/reasons | `fmt("%.1f", x)`, `py_repr(json)`, `py_float_repr(x)` |
| `ctx.cache[key]` | `ctx.cache.set<T>(key, v)`, `ctx.cache.get<T>(key)` (T must be copyable: each receiver package runs on a copy of the cache; use `shared_ptr` for big or move-only data) |
| `signal.features["_emissions"]` | `signal.emissions` |
| `decode.base.result(...)`, `receiver_signal`, `overlaps` | same names in `decode/plugin.hpp` |
| `EmissionReceiver` subclasses | `decode/emission_adapter.hpp` (`key()`, `bands()`, `run_detector()`, hooks) |
| `scipy.fft.fft/ifft/rfft` (any dtype), `np.fft.*` on float64/complex128 | `fft::fft`, `fft::ifft`, `fft::rfft`, `fft::irfft` |
| `np.fft.fft` / `np.fft.rfft` on float32/complex64 | `fft::np_fft`, `fft::np_rfft` (numpy 2.x computes these in double and casts to complex64) |
| `np.fft.ifft` / `np.fft.irfft` on complex64 | `fft::np_ifft`, `fft::np_irfft` (single precision, scale `float32(1)/n`) |
| `np.median`, `np.percentile`, ... | `si::np::` (numpy semantics, incl. float32 pairwise sums) |
| `scipy.ndimage.*`, `scipy.signal.*` | `si::ndi::`, `si::sig::` |

**Floating point.** Everything is compiled with `-ffp-contract=off` (no fused multiply-add),
because a Python expression `a*b + c` is two separate numpy operations. The exception is
`core/fft.cpp`: it wraps the exact pocketfft commit numpy 2.x and scipy vendor and is compiled
with the compiler's default contraction, as numpy/scipy are, so FFTs are bit-identical to
Python on the same platform (`tests/unit/test_core_fft.cpp`). numpy's own compiled loops
(complex multiply, `**`, BLAS dot) may still differ in the last bit; parity is judged on the
report (same decisions, numbers within one unit of the last printed decimal).

numpy behaviours that reach the report, found during the receiver ports:
- **Complex multiply:** numpy's loop rounds like `fma`, so use `np::cmul` / `np::cabs`, not `std::complex`
  operators.
- **Speed without changing results:** write hot per-element loops so they vectorise with the same operations in
  the same order: `np::cabs` is branch-free, `np::cmul_n` multiplies arrays, `np::median_inplace` uses a radix
  histogram before `nth_element`, and `ndi::uniform_filter1d(axis=0)` runs all columns at once. Keep sequential
  sums (cumsum, running filters) sequential. Check with `-Rpass-missed=loop-vectorize`, and require reports
  byte-identical (minus timings) to the previous build on all testdata.
- **Complex divide:** numpy uses Smith's method and multiplies by `1/b`, even when the divisor is a real cast to
  complex (`z / n`). Use `np::cdiv`.
- **Temporary elision:** on arrays of 256 KiB or more, numpy reuses the temporary in `a * np.conj(b)` and computes
  `conj(b) * a`. The operand swap changes the fma rounding. Mirror it, as rc_link `mul_conj(..., elided)` and
  emitters `cp_stage` do.
- **Complex exp:** `np.exp(1j*x)` is libm `cexp`, which on Apple is `__sincos` and can differ from `sin`/`cos` in
  the last bit. See `expj` in dji and emitters.
- **Rounding:** `round(np.float64, n)` is `np.round` (`np::round`), while `round(float, n)` is correctly rounded
  (`py_round`). `np.mod` and Python `%` take the sign of the divisor (`np::mod`).
- **BLAS and LAPACK:** convolve, correlate, vdot, norm, lstsq, inv and polyfit agree only to rounding. This has
  never changed a reported value.

Port line by line first (same order of operations, same dtypes, same tie-breaking: numpy
`argmax` takes the first maximum, `argsort` is stable only with `kind="stable"`), then optimise
where profiling says so (preallocate, avoid copies, `parallel_for` over independent hypotheses
with ordered results). No `-ffast-math`.

## Verification (definition of done)

1. Unit tests for the receiver's pieces against vectors written by the Python code
   (`tests/vectors/<name>/`, generated by a script in that folder).
2. Parity on testdata: `python c++/tools/parity.py --cpp <build>/si_analyze --receivers <name>`
   — same signals, labels, decode status and decoded fields as Python; numbers within one unit
   of the last decimal Python prints. Record the result in the receiver's README and in
   `c++/README.md` (status table). A difference that cannot be removed (e.g. a float32 tie) is
   documented with the input and field, never hidden.
3. `tools/check_modularity.py` passes; the full `si_tests` pass.

## Building (8 GB RAM, little disk)

```
cmake -S c++ -B c++/build -G Ninja -DCMAKE_BUILD_TYPE=Release
nice -n 19 ninja -C c++/build -j2
c++/build/si_tests
```
Use `-j2` and Release builds only (no debug info). One receiver alone:
`-DSI_RECEIVERS="lte;nr"` (a separate build directory per experiment; delete it after).
